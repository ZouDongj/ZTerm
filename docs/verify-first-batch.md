## 1. 回归：SSH 密码连接（优先级最高，确认没改坏）

- [ ] 连接 ssh.example.com（密码认证）
- [ ] 预期：正常登录，终端可用，无报错
- [ ] 连接 192.168.1.100
- [ ] 预期：正常登录
- [ ] 断开 → 重连 → 正常（重复 2 次）

## 2. H3：连接中关闭 tab → 无孤儿会话

- [ ] 连接一台**慢速/不可达**服务器（如把端口改成 22 但 IP 不可达，或连 192.168.1.100 时拔网线）
- [ ] 终端显示 "Connecting to ..."（尚未成功）时，**直接关闭该 tab**
- [ ] 预期：
  - 关闭后无报错弹窗（不应弹出 SSH 错误 toast）
  - 等待 10-20 秒，**不应出现**任何延迟的 "[SSH Error]" 提示
  - 服务器侧（如可达时）不应残留 sshd 会话进程

## 3. H4：连接中点击重连 → 无双连接

- [ ] 连接慢速/不可达服务器（"Connecting..." 阶段）
- [ ] 点击 tab 上的 ↻（重新连接）按钮
- [ ] 预期：
  - 最终**只有一个**连接进程（无双 shell）
  - 若服务器可达：服务器上 `who` 只显示一个会话
  - 无 "Connecting..." 卡死状态
- [ ] 变体：连接中切走 tab → 切回（switchTo 自动重连）→ 同样无双连接

## 4. H2：确认弹窗 Escape 后监听器不泄漏

- [ ] SSH 管理 → 对配置 A 点"删除" → 弹窗出现 → **按 Escape 关闭**
- [ ] 再对配置 B 点"删除" → 点弹窗"删除"按钮
- [ ] 预期：**只有 B 被删除**，A 仍然存在（修复前 A、B 都会被删）
- [ ] 变体：hostkey 弹窗——连一台 hostkey 变更的主机 → 弹窗 → Escape → 再次连接 → 弹窗 → 点"拒绝" → 不应有上一次的"信任"被误执行

## 5. H5：拖拽分屏 tab 到分屏 tab → 无幽灵叠加

- [ ] Tab A：分屏成 3 个 pane（Ctrl+Shift+H 分两次，或分屏后拖 tab 进来）
- [ ] Tab B：分屏 ≥2 pane，并让 B 处于**激活**状态
- [ ] 按住 Tab A 标签拖进内容区，在 B 的任一边缘 zone 释放
- [ ] 预期：
  - A 的 focused pane 并入 B，**视图显示 B 的布局**
  - 无 A 剩余 pane 叠在 B 上的情况
  - 输入/点击落到 B
  - 状态栏/标签高亮一致
- [ ] 变体：拖 A 到单 pane 的 tab C → 分屏正常

## 6. H1：SSH 密钥认证（如有密钥）

- [ ] SSH 管理 → 新增/编辑连接 → 认证方式选"密钥" → 填私钥路径（如 `C:\Users\z7614\.ssh\id_ed25519`）→ 保存
- [ ] 连接该主机
- [ ] 预期：免密登录成功（修复前必然 "Authentication failed"）
- [ ] 负向：填一个不存在的私钥路径 → 预期显示 "SSH key read: ..." 明确错误（而非模糊的认证失败）

## 7. H6：关闭已连接 SSH tab → 会话立即断开

- [ ] 连接 ssh.example.com 成功
- [ ] 服务器上执行 `who` 记下会话
- [ ] 关闭该 tab
- [ ] 预期：服务器侧会话**立即**消失（修复前可能残留到超时）
- [ ] 本地终端 tab 关闭 → 进程立即退出（`tasklist | findstr powershell` 无残留）

## 8. H7：config.json 损坏保护

- [ ] 退出 ZTerm
- [ ] 备份 `%APPDATA%\ZTerm\config.json`，然后写入非法内容（如 `{broken`）
- [ ] 启动 ZTerm
- [ ] 预期：
  - 出现 toast「配置文件已损坏，已备份并恢复默认设置」
  - 数据目录出现 `config.json.corrupt-<时间戳>` 备份文件
  - 软件正常启动（默认配置），**不会**立刻覆盖损坏文件
- [ ] 恢复原 config.json（删掉 corrupt 文件）
