# ADR-0001：稳定标签命中区域与安全的 TUI 光标接管

用户确认两个现象：鼠标扫过含 SSH 标签的 tab 栏时容易卡顿甚至卡死；herdr 中 **dsh-tui、kimi code 输入框**在输入时动画较正常，**删除文字或仅左右移动插入点时都会出现两个光标**。后者不是鼠标指针或软件外层tab焦点的问题。本决策采用**悬停不改变标签几何**和**不破坏文本语义的单一光标接管**，替代继续叠加悬停冷却与删除 styled-space 的修补方式。

`accepted` 表示用户已同意设计方向并要求形成实施依据，不表示已实现、已定位全部现场原因或已通过验收。本文包含两个可独立交付的工作包，先处理 tab 卡死，再处理输入框光标。术语见 [CONTEXT.md](../../CONTEXT.md)。

### 本 ADR 要解决

1. SSH/长名称标签在悬停扫动、停留和快速重入时的布局反馈、卡顿及错误展开状态。
2. herdr 内 dsh-tui、kimi code 输入框在删除和纯左右移动时的重复光标；同时保护文字擦除、位置、内容不变的导航，以及输入时已有平滑表现。

### 非目标

- 不更换字体、字形图集、抗锯齿策略、主题、终端尺寸算法或 90ms 曲线；不重开字体对标实验。
- 不关闭整个软件的动画；新增、关闭、重排等显式操作的动画不是“悬停几何动画”。
- 不在本轮顺带修复所有白盒发现：最后两标签关闭竞态、重复重连、混合 pane 配置迁移、标签溢出等另建工作包。若阻塞本轮真实路径，记录依赖并由主代理裁决。
- 不承诺通用识别所有 TUI 软件光标，不根据进程名称、窗口标题或一条看起来像光标的 ANSI 序列自动宣称支持。

## 3. 决策 A：悬停揭示与标签布局分离

### 3.1 不变量

- 对同一组内容、连接状态、窗口尺寸，**仅改变 hover/focus 状态不应改变任何标签及相邻标签的布局矩形**。
- SSH 重连动作有稳定的预留槽位；出现/隐藏动作只改变绘制可见性，不扩张槽位。适用于正常重连与断线重连状态，避免两个类各自保留不同的尺寸动画。
- 隐藏动作不拦截鼠标，不成为不可见点击目标；键盘操作必须能让对应动作清楚可见，不能以 `opacity:0` 作为唯一隐藏机制。
- 长名称保持截断，由共享提示展示全文；提示不推动布局、不夺焦点、不参与指针命中。
- 悬停不触发终端 fit、PTY resize、SSH 操作或全窗口重新渲染。

### 3.2 建议实现落点

| 文件 / 符号 | 修改要求 |
| --- | --- |
| `src/renderer/app.css`：`.tab`、`.tab-reconnect-normal`、`.tab-reconnect` | 删除 hover 引起的 max-width/槽位宽度变化。为 SSH 动作稳定预留空间，保留颜色/opacity 动效；不要误删 `.tab-exit` 等显式操作动画。 |
| `src/renderer/tabs.js`：末尾共享 hover IIFE | 删除为 hover 扩宽服务的测量、expanded/lastCollapsed/cooldown 状态机。保留一个共享提示，hover 只切换目标标识和提示内容。 |
| 同文件：`render` 的重连/关闭动作、`_onTabPointerDown` | 如果需要将动作改成语义 button，使用 type=button。拖拽入口排除动作按钮、输入框、可编辑区域；动作点击不触发 tab 拖拽。该排除是本工作包必需的交互保护，不扩展为拖拽系统重写。 |

tooltip 应按 tab/action 的稳定标识处理，而非把其内部 span/svg 的每次 mouseover 当作新目标。跨内部子元素移动不重启同一提示；切换、删除、重渲染、离开窗口时清理过期目标和 timer。定位只在确有新目标/位置变化时做一次“读布局→写样式”，不在事件里交替写宽度和测所有邻居。

`contain:layout style` 与 `will-change` 可暂保留，但它们不是 max-width 动画可以免除主线程布局的证明。不要再用增加 GPU 提示或延长冷却来替代稳定几何。

### 3.3 首轮诊断与验收

此前该症状已有多次修补，本轮遵守 `ui-transition-debug`：先做一次有上限的旧版采样，再做同条件新版采样。用真实 tab DOM 和本地虚构会话状态即可；无需真的连接服务器。

采样范围仅包括：指针轨迹、hover 目标变化、外层 tab/重连槽/相邻 tab 的宽度位置、相关 JS/布局耗时、是否发送 fit/resize/连接动作。避免在每个事件里额外强制布局；使用限定时长、批量读写或浏览器 tracing，记录观测扰动。若旧版可能卡死，用独立实例与外部超时保护，不能拿用户工作窗口试。

必须满足的检查：

| 场景 | 必须观察到的结果 |
| --- | --- |
| 普通/SSH/设置混合标签，多次横扫及反向 | 仅 hover 时矩形不变；颜色/提示正常；无自维持的布局/事件循环。 |
| 长名称、窄窗口、指针停在邻接边界 | 名称可通过提示读取；静止后有界收敛，无反复展开/收回。 |
| 离开后20ms/100ms重入，点击后移到同一tab子元素 | 不再发生永久截断/提示状态卡住；不依赖“再移出一次”恢复。 |
| 连接/断线动作可见性，键盘导航，重命名 | 动作可辨认可操作；隐藏时不截获；编辑文字不会开始拖拽。 |
| 关闭/拖拽/切到设置页 | 原有操作仍可用；本修复不引入新焦点抢夺、残留提示或错误会话操作。 |

自动化中可断言 hover 前/中/后矩形在测量精度内一致（初始容差0.5 CSS px，不得通过放宽容差掩盖动画），停止鼠标后等待正常 opacity/tooltip 过渡结束，确认没有持续几何写入。长任务/帧时以同机对照和归因记录报告；不要编造“144fps稳定”或仅凭JS计时宣布不卡。

**A完成条件**：几何与交互回归通过，真实原生窗口的限定扫动不再复现卡死，观测能解释被移除的反馈；若仍卡，保存 trace 并继续定位下一条具体路径，不能仅因删了动画就宣称修好。

## 4. 决策 B：原始内容正确性优先，明确且唯一地接管软件光标

### 4.1 原则与边界

1. 协议输入位置、软件绘制位置、动画视觉位置是三个不同概念，不能互相代替。
2. 识别光标不等于有权删除字符写入。正常写字、空格覆盖、erase、换行和当前字符属性必须由原始 VT 语义决定。
3. 软件光标接管只作用于有明确证据的原子呈现单元。未知、歧义或证据失效时完整回到原始显示；不是“继续沿用上一次猜测”。
4. 不接管时可有协议光标、软件光标或合法无光标；目标不是强行让每个画面有一个光标，而是**不额外制造重复光标**。
5. 接管后的坐标、宽度、形状及必要底层样式必须已知。无法可靠取得时允许降级，但必须报告支持缺口，不能把失去平滑当作最终完成。

### 4.2 B0：先构造删除与纯左右移动的反馈回路

复用已有 `tests/fixtures`，但区分“真实捕获”和“按模式重建”。先以匿名虚构文本建立最小反例，再在隔离、由自己创建的本地测试会话中确认 dsh-tui/kimi 对应输出形态。当前用户远程 herdr 里运行的 Agent 不可作为输入实验对象。

每份样本记录：客户端版本/启动方式、直连还是经过本地 ConPTY、原始输出及分块边界、是否使用同步输出、光标候选格与最终协议位置、原始/接管两路解析和显示结果。过滤前采样；现有经过 fix 后的缓存不是原始证据。保密内容不进入fixture；不得打印凭据或把原始工作会话上传给第三方。

至少取得向前输入、**内容不变的纯左/右导航**、行尾Backspace、移到文字中间删除、删空五类输入。纯导航先用虚构文本 `ab cd`：从行尾逐格左移到行首，再右移回行尾，覆盖非空字符、内部空格和末尾空格；另测连续按住方向键与快速反向。每一步内容必须不变，只有插入点变化。两个目标客户端分别留样本，不能只用一个通过就宣布另一个也兼容。针对当前“双光标”分类确认：

- 软件光标未被替换；
- 上一视觉位置没有重绘清除；
- 本应隐藏的协议光标被强制显示；
- 或这些原因组合。

原始路径与候选路径共用同一解析器/renderer和条件。文本/位置断言与逐帧视觉证据分开；仅有光标计数或终点相同不足以验收残影。完整运动过程不得只采尾部128次提交；提交时间不是呈现时间。

### 4.3 B1：先关闭不安全的启发式接管

将 `ipc.js::_conPtyCaretFix` 的“对字符串输出一律fix”改为显式策略边界。不能通过名字为 ConPTY 的函数对SSH流统一删除HIDE和styled-space，也不能只按标签显示名判断传输方式。

- 对尚未验证的 painted-caret 路径，先原样透传，停止删除整个 styled-space 和无条件SHOW。
- 原有确实需要的本地ConPTY可见性修复与软件光标接管分开判定。只有经过独立证据确认的局部修复才保留；无法区分的旧行为也必须降级并记录，不静默恢复粗放修复。
- 使用明确的单会话/单pane策略或适配器选择边界；普通协议光标继续用现有平滑实现。无需先做复杂用户设置页面。
- fallback 不显示额外自绘光标，并清除上一接管帧产生的纯视觉残留，不等待应用下次输入才清理。

**B1只算安全止血，不算B完成。** 如果删除时只剩原软件光标但完全不平滑，交付必须明确这是临时降级，继续B2或说明具体阻塞。

### 4.4 B2：原始流解析 + 光标描述 + 绘制期接管

首选结构是在不改写原始内容的情况下产生旁路“光标描述”，由现有同一 WebGL renderer 接管呈现。只加当前确实需要的窄模块；不要写第二个完整VT终端或通用TUI识别平台。

```text
原始输出 ──────────────→ 原有xterm解析器 ─→ 真实单元格/协议状态
    └→ 有界、只观察的特定模式识别 ───────→ 本帧光标描述
真实单元格 + 本帧描述 ─→ 原有同一WebGL绘制路径 ─→ 原始显示或唯一平滑光标
```

“描述”所需的信息如下，具体类型/模块名由实施者按现有结构确定，不要求照搬接口框架：

| 信息 | 必须满足的含义 |
| --- | --- |
| 会话/pane标识与generation | 不跨连接、pane、缓冲区或重启使用旧候选。 |
| 呈现单元标识、原始流序号与解析完成水位 | 描述只对应已可靠提交的当前画面；与buffer不属于同一完成水位、未完成/超时/超限不能强行接管。 |
| 软件光标的buffer坐标及宽度 | 来自确切绘制位置，包含坐标空间和宽字符规则；不可用末尾CUP冒充。 |
| 当前覆盖字符与原始属性 | 来自解析完成后的当前内容，删除为空格就必须保持空格，不能恢复上帧旧字。 |
| 可恢复的非光标表现及依据 | 用于去除软件光标的视觉样式；只能来自已验证的应用绘制约定/明确属性证据，不猜相邻背景或把旧字符整体拷回。 |
| 软件光标存在/可见性证据、形状、有效性与失效原因 | 与协议光标的DECTCEM状态分开记录；原子判定是否可接管，不确定就原始显示，不能把旧描述永远锁住。 |

**可判定性限制**：任意一个带色空格也可能是普通高亮、选区或装饰。仅靠它的颜色、连续出现两次或后面有CUP，无法通用地证明是光标。第一版只支持取得证据的客户端输出形式；空格与非空格、等价SGR必须有对应样本。单纯应用名称不是授权删除内容的证据。

具体接管规则：

1. 原始ANSI始终按其原意进入xterm，文本缓冲不被“去光标”逻辑修改。旧filter旁路不得同时继续改写同一流。
2. 完成帧后，若描述可信，仅在绘制期将该格的软件光标外观还原为已知非光标外观；文字与擦除后的内容保留。使用现有glyph/rectangle路径，不新建可见光标canvas、不移动整块终端。
3. 再绘制一个平滑光标，目标为描述坐标；这时即使协议光标被停放/隐藏，也不能额外显示它。若临时借用renderer状态，必须try/finally归还，不能把SHOW写回应用协议状态。
4. 删除导致新旧覆盖位置或宽字符范围变化时，重绘旧、新位置及移动跨度涉及的脏格/行。临时glyph与底色信息不能沿用过期字符，也不能只画新位置而留下上一帧的块。
5. 识别、去除旧软件光标外观、绘制新光标属于一次原子呈现：不能先强制显示再等后续帧确认匹配。
6. 在两个相邻且都可信的描述间，沿用现有90ms重定向；软件接管/协议模式切换、resize/scroll/断线等坐标失效边界应取消旧动画或snap到明确位置，避免从无关旧锚点飞过来。

如果当前私有renderer接口不足以安全做绘制期覆盖，先提交“缺少哪个可验证接口、最小补丁范围、对字体golden的风险”，由主代理裁决后再做窄改；不能悄悄改vendor/minified代码，也不能转回粗放字节删除。

#### 异步解析提交约束（必须落实，不能只写成注释）

旁路观察器读到第N个完整单元时，`term.write`可能尚未解析到N；一个write也可能同时含N和N+1。定义并使用每会话有序的原始流序号、解析完成水位及buffer generation，让渲染描述与**当前已解析buffer的同一提交点**绑定。

- 观察器只产生待提交候选，不直接更新活动渲染描述。先核实本版本xterm的write callback/解析事件语义，以确定可靠完成点；不能用一次setTimeout或rAF推测已经解析完。
- 活动描述只有在候选所对应单元完整、解析水位匹配、generation一致时才发布。如果一次write解析了多个单元，没有可靠中间检查点就只发布与末尾当前buffer一致的候选；禁止N帧描述配N+1内容。
- 后续原始数据可能影响候选格/坐标/来源时，在解析开始前就撤销旧描述资格（保守做法可在入队前撤销），直到新的完成点重新核验。绝不能边更新buffer边沿用旧遮罩或旧覆盖字符。
- xterm正常绘制、适配器直接rAF continuation、resize/refresh等所有入口共享该资格检查；任一入口发现水位不匹配就不增加接管光标，并按当前原始模型清理旧的纯视觉覆盖。
- 明确核对本版本对同步输出序列的实际支持和自定义continuation是否绕过它。看见`?2026h/l`本身不证明原子呈现已经得到保证。
- 原始输出的顺序和活性不依赖识别成功；只为光标观察新增的队列/缓冲必须有界，且不能制造第二套完整终端解析器。

#### 两种可见性不能混用

普通协议光标模式尊重应用的DECTCEM/形状/闪烁；可信软件接管模式尊重软件光标在已提交画面中存在、可见的证据。**DECTCEM持续隐藏协议光标不应单独禁用软件接管**，同样DECTCEM显示也不应使两个来源同时绘制。软件光标明确被撤销、覆盖或无法确认时，撤销接管。来源切换与上述提交点绑定，在一帧内互斥完成；不能先SHOW协议光标、下一帧再隐藏软件层。

### 4.5 接管状态与降级

| 当前证据 | 显示决策 |
| --- | --- |
| 普通应用管理协议光标 | 保留原始协议可见性/形状，使用现有协议光标动画能力；不启用软件接管。 |
| 检出候选但位置/底层样式不充分 | 原始显示，不添加第二光标；继续观察已限定的适配形式。 |
| 当前呈现单元全部证据充分 | 绘制期接管，本单元只有一个对应编辑光标。 |
| 新单元不匹配、软件样式改变、多个歧义候选 | 撤销接管、清除旧视觉残留、完整原始显示，不能只增计数继续SHOW。 |
| 会话/缓冲切换、丢帧/超限、renderer失效 | 丢弃旧描述与临时状态，安全恢复；下次重新取得证据。 |

“当前单元无新候选”不必表示静止光标立即消失：只有适配器能证明该单元未影响已有候选格、坐标及可见性时才可保留描述；否则降级。禁止无限期沿用旧候选。这条需有“无关区域更新”和“候选格被覆盖”两个反向测试。

观察器按原始分块连续解析，不把IPC边界当帧。原始输出不因观察器而无限等待；观察状态设置明确容量/时间边界，失效只关闭接管。分块、嵌套/损坏同步序列、UTF-8、reset路径需覆盖；不要为凑同步边界重排或丢掉原始输出。

## 6. B测试矩阵与完成条件

| 场景 | 内容与光标断言 |
| --- | --- |
| ASCII行尾输入、逐字删除、连续按退格、删空 | 解析内容等价于原始流；无残字/残块；删除期间无一跳一滑双光标。 |
| 纯Left/Right：`ab cd`行尾→行首→行尾，不改文本 | 每步内容/字符属性语义不被接管破坏；移动中和停止后都只有原始意图对应的一个编辑光标，不能一跳一滑或留下旧格；覆盖字母/内部空格/末尾空格切换。 |
| 连续方向键、快速反向、中文宽字附近的纯导航 | 内容不变，视觉从当前位置连续重定向；新旧覆盖格及时清理，宽字范围正确；不得通过禁用全部导航动画假装达标。 |
| 左移到已有文字中间，Backspace与Delete | 当前字符保留/删除语义正确；支持的非空格光标单一平滑，不支持形式明确原始回退。 |
| 软件位置与最终协议停靠点不同 | 可信接管画在软件位置；不可信不强制显示停靠点。 |
| 原始`abcd`，第4格以caret-space覆盖 | 接管后内容必须是`abc `，不是`abcd`；不能依赖下一按键修正。 |
| 两次普通高亮空格、选区或装饰，后接CUP | 不因弱特征触发接管，不吞HIDE/不删正常内容。 |
| 字符/颜色表示变化：非空格、反色、256色、SGR分拆 | 每种已支持形式有fixture；未支持形式回退，不残留额外光标。 |
| 中文宽字、跨行与长输入 | 字符/宽字尾格正确；沿用已约定的大跳snap，不能用其解释同格范围双光标。 |
| 同样流以1字节、多字节、整块及随机分块输入 | 文本、候选位置、接管决策一致；UTF-8不损坏。 |
| 无关区域更新、候选格覆盖、hide/show/shape改变 | 保留或撤销描述有明确依据；分别按当前来源处理协议可见性与软件光标存在证据，旧视觉层及时清除。 |
| 协议光标持续隐藏，软件光标正常左右移动；随后软件光标明确撤销 | 前者仍可单一平滑接管，后者及时清除并回原始显示；不能将同一个HIDE信号误作两种语义。 |
| 延迟解析、同一write多个单元、单元跨chunk、解析期间触发continuation | 活动描述与当前buffer水位/generation匹配；不出现N帧坐标配N−1/N+1内容，不显示过期第二光标。 |
| 重连/reset、alternate buffer、resize、scroll、pane焦点、context loss | 不携带旧会话候选、无额外光标/迟到回调残影。 |
| 普通shell/nvim类协议光标、关闭动画/减少动态效果 | 不被软件识别误接管；普通光标行为不退化，静态回退正确。 |

先让旧实现对精确反例失败，再验证候选修复。原始缓冲完全不修改的方案应逐格对比字符、宽度及属性；如确有独立ConPTY协议修复，单独说明允许差异，不以宽松比较放过内容变化。

**B完成条件**：用户所用 **herdr+dsh-tui、herdr+kimi code** 的版本/传输场景分别具备输入、删除与纯左右导航样本；支持范围内单一光标且内容无损，原有输入平滑不退化，导航/删除不靠全局关闭动画规避，未知形式安全回退。移动中与停止后的原生目视/完整帧证据、自动断言共同通过。若只完成安全回退，状态应写“止血完成，软件光标平滑尚未完成”。

## 7. 顺序、门禁和证据交付

1. 固定基线、保存本工作包改前文件与构建标识；阅读旧probe后才决定是否复用。有些脚本会启动shell、向herdr发送内容或结束进程，不能直接运行。
2. A旧版限定复现/采样 → A稳定几何实现 → A交互与原生复核 → 独立交付。
3. B0原始删除/纯左右导航样本与反例 → B1安全边界 → B2限定模式接管 → 两个目标客户端的B矩阵与原生复核。
4. 两位独立reviewer分别审生命周期/协议正确性和真实路径/视觉证据；主代理复核发现。对于本ADR文档审查，不要求跑应用全量门禁；实现提交前必须按当前 `package.json` 跑项目 `npm run verify`。
5. 核对 `verify/e2e` 是否会触碰用户config、启动真实连接或旧会话；必须使用临时隔离配置/实例，不因命令被列为门禁就默认安全。禁止用正式工作的SSH会话验收。
6. 当前 `npm run verify` 包含Rust/前端测试、release构建、E2E；以实施时脚本为准。运行中的exe可能锁定构建目标，只能在验证精确绝对路径后结束自己创建的测试进程，不使用按映像名批量taskkill。
7. 新增/修改代码注释与提交信息用英文；文档可中文。移除高频临时日志，仅保留有上限的按需诊断与fixture。失败产物用独立目录，不能覆盖旧成功结果后混称通过。

每包交付一屏摘要：基线/有效diff、复现命令、旧失败/新结果、原始证据位置、支持和降级场景、未解决问题、回退方法。证据必须对应实际构建、DPR、有效动画设置与会话类型。终端字体golden和普通光标作为保护基线，范围不变时不重复历史字体研究。

两次针对性修复仍失败且无新证据时，停止当前方法，提交最小证据升级。新的调度器、全窗口动画关闭、正则越写越宽，都不是默认下一步。

## 8. 取舍与回退

| 备选 | 决定与理由 |
| --- | --- |
| 保留悬停扩宽，继续加rAF/冷却/合成层提示 | 不采用为最终方案：仍改变命中几何，且已有冷却状态缺陷。 |
| 关闭全部动画 | 不采用：会损失用户认可的光标体验，也掩盖局部问题。 |
| 稳定槽位 + 颜色/透明度 + 全名提示 | 采用：牺牲悬停挤开邻居的效果，换取可预测交互；多占的槽位宽度须检查长标签截断。 |
| 扩大正则并删除styled字符/空格 | 不采用：格式匹配不能证明光标身份，删除可能破坏内容。 |
| 全部软件光标永久原始显示 | 仅作为不支持/故障时回退：正确性好，但不能单独满足目标场景的平滑要求。 |
| 旁路描述 + 同WebGL绘制期接管 | 采用为目标：保留内容语义并明确唯一来源；成本是限定模式支持、脏区和状态生命周期测试。 |

A/B应独立可回退，不回滚无关字体、SSH业务或用户修改。A故障时保留稳定尺寸与基本动作，退掉提示/附加动效即可；B故障时按会话回到原始显示，撤销临时绘制覆盖与旧候选。**B安全回退不得重新开启原先无条件fix来“恢复动画”。**
