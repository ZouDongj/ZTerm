# ZTerm UI 一致性审计（2026-09-13）

> 数据来源：`node scripts/ui-consistency-audit.mjs`（可重跑复核），原始数据 `design/ui-audit-20260913.json`。
> 扫描范围：app.css + xterm.css（自维护部分）+ renderer.html 内联样式/样式块 + 14 个 renderer JS 的动态样式赋值。

## 一句话结论

强调色已经统一（`--accent-rgb` 用了 107 次），**但字号、圆角、间距、动效时长四个维度完全无栅格**——这是"不和谐感"的主要来源；键盘/按压交互态几乎缺失是次要来源。

## 病灶排序（按对观感的影响）

### 1. 字号：14 种值，其中三档几乎重合

`13px×20、12.5px×19、11px×19、12px×15、10px×10、10.5px×5、14px×5、15px×4、16/17/20/48px×1`

**13px / 12.5px / 12px 同时高频使用**——视觉上无法区分的三个档位各自承担"不同的语义"，层级信号全部丢失。10.5px 这种半档值同样在制造噪声。

**收敛建议**：6 档 —— `10 / 11 / 12 / 13 / 15 / 20`（+ splash 的大号一次性值）。删除 10.5/12.5/16/17。

### 2. 圆角：19 种值

`10px×14、9px×11、6px×10、50%×9、12px×9、16px×8、8px×8、5px×7、14px×6、2px×3` + 6 组混合角

同一个界面里按钮 6px、tab 8px、卡片 10px、浮层 12px、面板 16px、还有 5/9/14px 各自出现——圆角是最容易被余光捕捉的"不和谐"信号。

**收敛建议**：4 档 —— `--radius-s: 6px`（小控件/输入框）、`--radius-m: 10px`（按钮/卡片/tab）、`--radius-l: 14px`（面板/浮层）、`50%`（圆点/头像保留）。删除 5/8/9/12/16px。

### 3. 动效时长：10 种时长、34 种 transition 写法

`0.15s×40、0.2s×27、0.12s×11、0.1s×10、0.22s×7、0.25s×5、0.18s×4、0.4s×3、0.05s×1`

鼠标滑过不同按钮时快慢不一（0.1s 和 0.25s 相差 2.5 倍），"手感廉价"的直接来源。

**收敛建议**：3 档 —— `--dur-fast: 0.12s`（hover/焦点）、`--dur-med: 0.2s`（面板/展开）、`--dur-slow: 0.4s`（splash/大过渡），统一 ease 曲线 1 种 + 强调曲线 1 种。

### 4. 间距：25 种值，一半在 4px 栅格外

高频 off-grid：`10px×20、6px×10、7px×6、9px×5、14px×5、13px×3、11px×2、5px×3、26px×2、3px×2`

10px 是全站使用最多的间距但不在 8px 栅格上；7/9/11/13/14px 是"手动微调"痕迹。

**收敛建议**：采用 **4px 栅格** 8 档 —— `2 / 4 / 8 / 12 / 16 / 20 / 24 / 32`。7→8、9→8、13→12、14→16、26→24。

### 5. 交互态覆盖严重失衡

`hover: 65 处、focus: 12、:focus-visible: 0、:active: 2、:disabled: 0`

鼠标悬停反馈到处有，**键盘焦点环规范为零**（:focus-visible 从未使用）、按压反馈只有 2 处、禁用态无样式——键盘用户的焦点可见性靠浏览器默认，与整体风格割裂。

**收敛建议**：统一 `:focus-visible` 焦点环 token（`0 0 0 2px rgba(accent, 0.5)`）、按钮/列表项补 `:active`（背景加深 4%）、所有可禁用控件补 `:disabled`（opacity 0.45 + 无指针）。

### 6. 阴影：14 种写法（token 已有但只有 9 处使用）

`--shadow-float` token 存在且用了 9 次，但另有 13 处手写阴影（`inset 0 1px 0 rgba(255,255,255,0.05/0.055)`、`0 8px 24px rgba(0,0,0,0.45)` 等近似变体）。

**收敛建议**：表面层级定死 3 档 `--shadow-flat / --shadow-pane / --shadow-float`，inset 高光并入 token 定义，删除全部手写。

### 7. z-index：19 个魔法值无体系

`20、9999、10、5、300、50、1、9998、200、299、15、30、0、100、-5、6、7、8、2`

**收敛建议**：定义 5 层 —— `--z-base: 0 / --z-raised: 10 / --z-sticky: 20 / --z-overlay: 100 / --z-toast: 200`，9998/9999 归 overlay/toast。

### 8. 游离颜色（问题最小）

灰阶意外地干净（独立灰仅 2 个），强调色高度统一。游离项：
- `#8fc1ee×12、#9cc8ee×8`——两个近似蓝（链接/信息色？）未 token 化，应合并为 `--color-link`
- `rgba(255,255,255,0.04/0.045/0.05)` 三档几乎相同的白色微透明（表面叠加层）→ 收敛为 `--overlay-1`
- 状态色散落：`#7dd58a×6`（成功）、`#f19b92×4`（错误）、`#ffb74d×4`（警告）→ `--color-success/error/warning`

### 9. JS 动态样式绕过 CSS 体系

`tabs.js×16、ssh.js×10、command-palette.js×2、highlight.js×2、quick-commands.js×2、settings.js×2` 共 32 处 `el.style.xxx = ...`——tab 宽度/ssh 状态色等动态样式直接写在 JS 里，改 token 时会漏网。

**收敛建议**：JS 注入样式改为写 CSS 类（值留在 CSS），或注入 `style.setProperty('--xxx', val)` 走变量。

## Token 体系总蓝图（第二步的实施目标）

```css
:root {
  /* 已有 */ --accent-rgb, --accent-contrast, --term-bg, --surface-win/float/card,
            --text-1/2/3, --shadow-pane/float
  /* 新增 */ --radius-s/m/l
            --dur-fast/med/slow, --ease-std, --ease-emph
            --space-1..8  (2/4/8/12/16/20/24/32)
            --font-size-1..6 (10/11/12/13/15/20)
            --color-link, --color-success, --color-error, --color-warning
            --overlay-1, --z-base/raised/sticky/overlay/toast
            --shadow-flat
}
```

约 **25 个新 token + 8 个已有 token 扩展使用**，替换面覆盖 app.css 53KB 的绝大多数视觉声明 + renderer.html 内联样式 + 32 处 JS 注入点。

## 实施顺序（每步独立可回归）

1. **纯减法**（最低风险）：删除 10.5/12.5/16/17px 字号、5/8/9/12/16px 圆角 → 最近档位替换；0.05/0.18/0.22/0.25s → 三档时长。E2E 41 项 + 截图对照守护。
2. **加 token**：新变量定义 + 全量替换硬编码值（脚本辅助，人工复核 diff）。
3. **交互态补全**：focus-visible/active/disabled 三件套（新增样式，不改布局，风险最低但观感收益大）。
4. **JS 样式收编**：32 处动态样式改走 CSS 类或 CSS 变量。
5. （然后才是）方向试穿：redesign 系列任何一稿此时只需改 20 个变量值。

## 局限声明

- 本审计只覆盖代码层可量化维度；布局比例、视觉密度、信息层级这类需要看图的维度不在其中（最终仍需你肉眼验收）。
- `--surface-* / --text-*` 已有 token 的具体色值是否"好看"不属于一致性问题，留给方向试穿阶段。
